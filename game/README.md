# バースデー・デュエル（Birthday card game）

自分と同じ誕生日の有名人を手札にして、その場にいる仲間とカテゴリー別に「知名度」で勝負する、飲み会向けの Web アプリです。画面は白地に黒い太字とネオンのライムを差したデザインです。フォント（Noto Sans JP・Anton・Yellowtail）は Google Fonts から読み込み、読み込めないときは端末のフォントで表示します。

アプリでできるのは次の 3 つです。対戦相手とのやり取り、勝敗の判定、得点の管理はアプリの外で、その場の人たちが行います。

- 自分の誕生日の人物を探す
- カテゴリーから勝負に出すカードを選ぶ
- 勝負用のカードを大きく表示する

オンライン対戦、ルーム、参加者の登録、端末どうしの通信、CPU 対戦はありません。

## 遊び方

1. それぞれが自分のスマートフォンでアプリを開き、誕生日（月日）を入れる
2. みんなで「次は音楽で勝負！」とカテゴリーを決める
3. 各自そのカテゴリーのタブから 1 人を選び、「このカードで勝負」を押す（カードは伏せた状態になる）
4. 「せーの」で「せーので公開」を押し、画面を見せ合う
5. 知名度スコアが大きい人の勝ち（負けた人の罰ゲームはその場で決める）。「次の勝負へ」で手札に戻る

1 台を交代で使うときは「誕生日を変える」で切り替えます。同じ人物を何度使ってよいかなどのルールは、遊ぶ人どうしで決めてください（アプリでは制限しません）。

## 起動方法

Node.js 20.9 以上が必要です。

```sh
cd game
npm install
npm run dev        # 開発用  http://localhost:3000
# または
npm run build && npm run start   # 本番用
```

- **デモモード:** `http://localhost:3000/?demo=1` を開くか、誕生日入力画面の「デモモードで試す」をオンにします。デモデータがある誕生日は 10月29日・2月29日・1月1日です。
- **みんなのスマホで開く（同じ Wi-Fi）:** `npm run play` で起動します（本番モードでビルドして、同じネットワークの端末から開けるようにします）。ターミナルに出る `Network:` の住所（例: `http://192.168.1.23:3000`）をスマホのブラウザーで開いてください。
  - `npm run dev`（開発モード）でもスマホから開けます。ただし Next.js 16 の開発サーバーは localhost 以外からのアクセスを止めるので、`next.config.ts` で家庭や店のネットワークのアドレス（`192.168.*.*`、`10.*.*.*`、`172.*.*.*`、`*.local`）を許可しています。ほかのアドレスから開くときは `ALLOWED_DEV_ORIGINS=アドレス npm run dev` のように足してください。許可されていないと、画面が「読み込み中…」のまま止まります。
- **外のネットワークから開く:** インターネット上に公開します（例: Vercel に `game/` をルートディレクトリとして登録）。

### その他のコマンド

| コマンド | 内容 |
| --- | --- |
| `npm test` | 単体テスト（ネットワークを使わない。外部 API はモック） |
| `npm run typecheck` / `npm run lint` | 型チェック / lint |

## 画面

1. **誕生日入力:** 月日だけを入力します（2月29日も選べます）。誕生日は端末の localStorage に保存され、変更とリセットができます。
2. **手札一覧:**
   - カテゴリーのタブで切り替えます。「図鑑」タブには全員が出ます。
   - カードには名前、画像（なければ頭文字とカテゴリーの絵の代替ビジュアル）、短い紹介、カテゴリーが出ます。
   - 知名度スコアは、一覧にも詳細にも選択中にも出しません。
   - カテゴリーのタブでカードをタップすると選択され（ライムの枠と「選択中」）、画面下の「このカードで勝負」で勝負に出します。カード左上の「i」で、詳細（生年月日、職業、出典リンク、画像のクレジット）が開きます。
3. **公開待ち:** 名前もスコアも出さないカード裏面と、大きな公開ボタンを表示します。公開前なら「選び直す」で選び直せます。選んだカードは端末に保存されるので、ページを再読み込みしても伏せた状態のまま残ります。
4. **公開:** カードをめくる演出のあと、名前・画像・カテゴリー・スコアを大きく表示します。ローマ字の名前（Wikidata の英語名がラテン文字のときだけ）があれば、画像の上に筆記体のサインとして重ねます。あわせて、スコアの説明、集計期間、データ取得日も出します。

設定画面でできること:

- 「センシティブな人物を隠す」のオン・オフ
- 「アニメーションを減らす」のオン・オフ（端末の「視差効果を減らす」設定にも従います）
- デモモードの切り替え
- 「このカードを外す」で外したカードを戻す
- 誕生日のリセット

## カテゴリー

| カテゴリー | 含める職業（Wikidata の Q-ID とその下位分類） |
| --- | --- |
| 芸能 | 俳優、声優、コメディアン、テレビ司会者、モデル、映画監督、YouTuber |
| 音楽 | 音楽家、歌手、作曲家、指揮者、作詞作曲家、ラッパー、DJ |
| スポーツ | スポーツ選手、プロレスラー、サッカー監督 |
| 知・発明 | 科学者、発明家、数学者、哲学者、技術者、医師、宇宙飛行士、研究者 |
| 歴史・社会 | 政治家、君主、軍人、活動家、外交官、武士、探検家 |

分類のしかた:

- 人物の職業（P106）が上の職業そのものか、P279（下位分類）をたどってそこに着けば、そのカテゴリーに入れます。職業名の文字列一致は使いません。
- 複数の分野で活動する人は、複数のカテゴリーに出ます。
- どこにも当てはまらない人（作家、画家など）は無理に割り当てません。図鑑タブには「部門なし」として出ますが、勝負には使えません。
- ルールは `lib/categories.ts` にまとまっています。Q-ID を足したり除いたりするだけで変更できます。変更したら `npm run check-categories` で、意図した職業を指しているか確認してください。

## データの取り方

```
lib/server/birthpage.ts  その日生まれの人物の一覧（日本語版 Wikipedia の日付ページ）
lib/server/wikidata.ts   人物の詳細と職業の上位分類（Wikidata の API）
lib/classify.ts          カテゴリー分類・センシティブな人物の判定（ネットワークを使わない）
lib/server/images.ts     画像とライセンス（Wikimedia Commons API）
lib/server/pageviews.ts  知名度スコア（Wikimedia Analytics API の閲覧数）
lib/server/hand.ts       上をつないで、誕生日 1 つ分の手札を作る
lib/server/cache.ts      キャッシュ
app/api/hand/route.ts    画面から呼ぶ API（GET /api/hand?date=10-29）
components/              画面（実データとデモで共通）
```

外部 API へのアクセスはすべてサーバー側で行います。ブラウザーは `/api/hand` だけを呼びます。

### 人物（Wikipedia の日付ページ + Wikidata）

1. 日本語版 Wikipedia の日付ページ（「8月13日」など）の「誕生日」の節を読み、そこに載っている人物を手札の候補にします。人が選んで載せている「その日生まれの著名な人」の一覧なので、**その日生まれの全員ではありません**。
2. 各人物の記事名から Wikidata の Q-ID を引き（リダイレクトも解決）、Wikidata の API（`wbgetentities`）で名前・説明・職業・画像・生年月日を取ります。
3. Wikidata で「人間」と登録されていない項目（バンドやグループなど）は除きます。

最初は Wikidata のクエリサービス（SPARQL）で「その月日生まれの人」を検索していましたが、重すぎて時間切れになり、実際に使えませんでした。そのため、1 回で一覧が手に入る日付ページを使う方法に変えました。

- **名前:** Wikidata の日本語ラベルを使います。なければ英語、多言語共通のラベル、日本語版の記事名（末尾の括弧書きを除く）の順で使います。
- **説明:** Wikidata の日本語の説明を使います。なければ、日付ページの一覧に書かれている説明（「歌手」など）を使います。どちらもない人には「紹介文はありません」と出し、文章を作って補うことはしません。
- **並び順:** 生まれ年の新しい順です。知名度順に並べると、公開前にスコアの大小が分かってしまうためです。

### 誕生日の採用方針

- **誰をその日生まれとするか:** 日本語版 Wikipedia の日付ページの「誕生日」の節に載っている人です。年や月までしか分からない人は、そもそも日付ページに載りません。
- **表示する生年月日:** Wikidata の生年月日（日の精度まで分かる、最良ランクの値）の月日がその日と同じなら、それを表示します。同じでなければ（旧暦・ユリウス暦の違いや記録の食い違いなど）、日付ページに書かれた年と、その日の月日を表示します。
- **複数の誕生日:** Wikidata に生年月日が複数あるときは「最良ランク」の値だけを見ます（推奨ランクがあればそれ、なければ通常ランク。非推奨ランクは使いません）。
- **暦の違い:** Wikidata の生年月日がユリウス暦で記録されていて月日が一致した人には、詳細画面で注記します。日付ページ側の暦の扱い（旧暦の換算など）は、Wikipedia の記載に従います。

### 知名度スコア（Wikipedia 閲覧数）

- **数えるもの:** 日本語版 Wikipedia の記事が、人間によって閲覧された回数（agent = `user`、全アクセス方法）の合計です。この合計をそのまま比較値にします。補正はしません。
- **集計期間:** 「直近の完了した月の末日までの 12 か月」です。UTC で計算するので、どの端末でも同じ期間になります（例: 2026年10月29日なら 2025年10月〜2026年9月）。月が変わると、全員の集計期間がそろって次の 12 か月に進みます。
- **値の固定:** 「このカードで勝負」を押した時点で、スコア・集計期間・取得日をカードにコピーして固定します。公開画面には集計期間を出し、期間の違うカードどうしを比べないよう注意書きも表示します。
- **0 回と取得失敗の区別:**
  - API が 404（その期間に閲覧記録がない）を返したときは、0 回として扱います。
  - それ以外の HTTP エラーやタイムアウトは「スコア未取得」とし、そのカードは勝負に使えません。一覧に再試行ボタンを出します。
- **記事名の変更とリダイレクト:** 閲覧数は、リダイレクトを解決した今の記事名で数えます。そのため、次の閲覧は合計に入りません。
  - 改名前の記事名での閲覧
  - リダイレクト（別名のページ）経由の閲覧
  
  期間の途中で改名された記事は、実際より少なく出ることがあります。

### 画像

- **使う画像:** Wikidata の画像（P18）を Wikimedia Commons で調べ、ライセンスと作者を確認できたものだけを使います。認めているのは、パブリックドメイン、CC0、CC BY、CC BY-SA です。
- **使わない画像:** フェアユースなど上記以外のライセンスの画像と、作者が分からない CC 画像は使いません。かわりに代替ビジュアルを出します。
- **クレジット:** 使った画像のクレジット（作者とライセンス）は、カードの詳細画面に表示します。

### センシティブな人物を隠す

既定でオンです（設定でオフにできます）。次のどちらかに当てはまる人物を手札に出しません。

- 職業（下位分類も含む）が「ポルノ俳優」「犯罪者」「連続殺人犯」
- 日本語の説明に「AV女優」などの語がある

Wikidata の記録に頼っているので、完全ではありません。漏れた人は、カードの「このカードを外す」で外せます（端末に保存され、設定画面で戻せます）。判定ルールは `lib/categories.ts` にあります。

## キャッシュ

| どこ | 中身 | 有効期間・更新 |
| --- | --- | --- |
| サーバーのメモリとディスク（`data/hands/<集計期間>/<月日>.json`） | 誕生日 1 つ分の手札（人物・分類・画像・スコア） | 集計期間が同じあいだ有効。月が変わると集計期間が変わり、キーも変わるので、自動で新しく取り直す |
| 端末の localStorage | 誕生日、設定、外したカード、選択中のカード | 利用者が変更・リセットするまで |

- **初回の取得:** ある誕生日を初めて開いたときは、日付ページの読み込み（1 回）、Wikidata への問い合わせ（50 人ずつ数回）、勝負に使える人数分の閲覧数取得をまとめて行います。十数秒〜数十秒かかる見込みです（この環境では実測できていません）。職業の上位分類は、サーバーが動いているあいだ使い回します。2 回目以降と、同じ月に同じ誕生日を開いた人は、キャッシュからすぐ表示されます。
- **同時アクセス:** 同じ誕生日の取得が同時に始まった場合は、1 回にまとめます。
- **スコアの再取得:** 取得に失敗したスコアは、再試行ボタンでその人の分だけ取り直します。
- **前もって取得する:** `npm run prefetch` で取得しておけます。サーバーレス環境（Vercel など）ではディスクの内容が残らないことがあるため、よく使う誕生日を prefetch して、`data/hands/` を一緒にデプロイするのが確実です。その場合は `.gitignore` の `/data/hands/` を外してください。
- **キャッシュを捨てて取り直す:** `data/hands/` の該当ファイルを消して、サーバーを再起動します。
- **保存先:** `HAND_CACHE_DIR` で変えられます。書き込めないときは OS の一時ディレクトリを使います。

### 環境変数（すべて省略可）

| 変数 | 既定値 |
| --- | --- |
| `JA_WIKIPEDIA_API` | `https://ja.wikipedia.org/w/api.php` |
| `WIKIDATA_API` | `https://www.wikidata.org/w/api.php` |
| `PAGEVIEWS_API_BASE` | `https://wikimedia.org/api/rest_v1/metrics/pageviews/per-article/ja.wikipedia.org/all-access/user` |
| `COMMONS_API` | `https://commons.wikimedia.org/w/api.php` |
| `WIKIMEDIA_USER_AGENT` | `BirthdayDuel/0.1 (...)`。公開するときは連絡先を含めてください（Wikimedia の User-Agent ポリシー） |
| `PAGEVIEWS_CONCURRENCY` | `12`（閲覧数 API への同時リクエスト数） |
| `HAND_CACHE_DIR` | `data/hands` |

## デモモード

- 人物はすべて架空で、スコアは「デモ値」と表示します。画面上部に「デモモード」の印を常に出します。
- 実データと同じ画面・同じカード操作を使います。
- デモで確認できるケース:
  - 複数のカテゴリーに入る人
  - 画像あり・なし
  - スコア 0
  - スコア取得失敗
  - 日本語版の記事なし（スコア対象外）
  - 部門なし
  - 「センシティブな人物を隠す」で隠れる人
  - ユリウス暦
  - 2月29日
  - 候補のいないカテゴリー（2月29日の「知・発明」）
- 実データの取得に失敗しても、自動ではデモに切り替えません。エラー画面に「再試行」と「デモモードで試す」を出し、利用者が選びます。

## 既知の制約

- **実データでの確認:** 開発環境のネットワーク制限で、Wikipedia・Wikidata・Wikimedia の API には接続できませんでした。取得処理は、API の応答や日付ページの書き方をまねたモックでテストしていますが、本物の API での動作と、取得にかかる時間は公開した環境で確かめる必要があります。
- **API 仕様:** 閲覧数 API の月別集計で、期間の最終月が含まれるかは、応答の月を数えて確認しています。期間外の月は数えません。API 仕様の確認はドキュメントに基づくもので、実際の応答では検証できていません。
- **分類ルールの Q-ID:** `lib/categories.ts` の Q-ID は、ネットワークに接続して確認できていません。最初に `npm run check-categories` を実行して、意図した職業になっているか確かめてください。
- **作家・画家・漫画家など:** 5 つのカテゴリーのどれにも入りません。必要なら `lib/categories.ts` に「文学・アート」カテゴリーを追加できます。
- **日付ページの書き方:** 日付ページの「誕生日」の節は、「* [[1990年]] - [[人物]]、説明」という行の形を前提に読んでいます。書き方が大きく違う行は読み飛ばします。
