# バースデー・デュエル（Birthday card game）

自分と同じ誕生日の有名人を手札にして、その場にいる仲間とカテゴリー別に「知名度」で勝負する、飲み会向けの Web アプリです。

公開中: https://birthday-duel-game.vercel.app

アプリでできるのは次の 3 つです。勝敗の判定や得点の管理は、その場の人たちが行います。

- 自分の誕生日の人物を手札として集める
- カテゴリーから勝負に出すカードを選ぶ
- 勝負用のカードを大きく表示する

オンライン対戦、ルーム、参加者の登録、端末どうしの通信、CPU 対戦はありません。

## 遊び方

1. それぞれが自分のスマートフォンでアプリを開き、誕生日（月日）を入れる
2. お題のカテゴリーのタブで 1 枚選び、「このカードで勝負」を押す（カードは伏せた状態になる）
3. 「せーの」で「せーので公開」を押し、画面を見せ合う
4. 知名度スコアが一番大きい人の勝ち（負けた人の罰ゲームはその場で決める）
5. 公開画面の「次は「〇〇」で勝負」で、次のカテゴリーの手札に進む

カテゴリーは 芸能 → 音楽 → スポーツ → 知・発明 → 歴史・社会 → 芸能… の順に進みます。どの端末でも同じ順なので、みんなが押せば同じお題になります。カードのないカテゴリーも飛ばしません（その人は「この勝負はパスしてください」と表示されます）。別のカテゴリーや同じカテゴリーでもう一度遊ぶときは、公開画面の下のボタンから選びます。

1 台を交代で使うときは「誕生日を変える」で切り替えます。同じ人物を何度使ってよいかなどのルールは、遊ぶ人どうしで決めてください（アプリでは制限しません）。

## 画面

1. **誕生日入力:** 月日だけを入力します（2月29日も選べます）。誕生日は端末に保存され、変更とリセットができます。「遊び方」から遊び方の説明を開けます。
2. **手札:**
   - カテゴリーのタブ（芸能・音楽・スポーツ・知・発明・歴史・社会）で切り替えます。「図鑑」タブには全員が出ます。
   - カードには名前、写真（なければ頭文字の代わりのカード）、短い紹介、カテゴリーが出ます。
   - カードをタップすると選択され（ライムの枠と「✓ 選択中」）、画面下の「このカードで勝負」で勝負に出します。押したときに、その人の知名度スコアを取ります（約 1 秒）。
   - カード左上の「i」で詳細（生年月日、職業、出典リンク、写真のクレジット）が開きます。「このカードを外す」もここにあります。
   - 知名度スコアは、公開するまでどこにも出しません。
3. **公開待ち:** 名前もスコアも出さないカード裏面（B/D のロゴ）と、「せーので公開」のボタンを出します。公開前なら「選び直す」で選び直せます。選んだカードは端末に保存されるので、ページを再読み込みしても伏せたまま残ります。
4. **公開:** カードをめくる演出のあと、写真・カテゴリー・名前・知名度スコアを大きく出します。ローマ字の名前があれば、写真の上に筆記体のサインとして重ねます。スコアの説明、集計期間、データ取得日も出します。

右上の「招待」ボタン（最初の画面と手札の画面）か、設定の「みんなを招待（QRコード）」で、アプリの QR コードを大きく出せます。その場の友だちに読み取ってもらうと、アプリが開きます。「リンクをコピー」と、スマホの共有メニュー（「LINE などで送る」）もあります。QR コードは、開いているアプリの URL から作ります（`?demo=1` は付けません）。印刷や送信に使える画像は、リポジトリの `share/`（`share-card.png`・`qr.png`）にあります。

右上のメニュー（☰）から設定を開けます。

- 「センシティブな人物を隠す」のオン・オフ（既定はオン）
- 「アニメーションを減らす」のオン・オフ（端末の「視差効果を減らす」設定にも従います）
- 外したカードを戻す
- 誕生日のリセット

デザインは、白地に黒い太字とネオンのライムを差したものです。フォント（Noto Sans JP・Anton・Yellowtail）は Google Fonts から読み込み、読み込めないときは端末のフォントで表示します。

## 起動方法

Node.js 20.9 以上が必要です。

```sh
cd game
npm install
npm run dev        # 開発用  http://localhost:3000
npm run play       # 本番モードでビルドして起動。同じ Wi-Fi のスマホからも開ける
```

- **同じ Wi-Fi のスマホで開く:** `npm run play` で起動し、ターミナルに出る `Network:` の住所（例: `http://192.168.1.23:3000`）をスマホで開きます。`npm run dev` でも開けるように、`next.config.ts` で家庭や店のネットワークのアドレス（`192.168.*.*`、`10.*.*.*`、`172.*.*.*`、`*.local`）を許可しています。ほかのアドレスから開くときは `ALLOWED_DEV_ORIGINS=アドレス npm run dev` のように足してください（許可されていないと「読み込み中…」のまま止まります）。
- **公開（Vercel）:** Vercel のプロジェクトに、このリポジトリを Root Directory `game` で登録しています。ブランチに push すると自動で公開し直されます。

## カテゴリー

人物の職業（Wikidata の P106）が下の職業そのものか、その下位分類（P279 をたどって着くもの）なら、そのカテゴリーに入れます。職業名の文字列では判定しません。

| カテゴリー | 含める職業（とその下位分類） |
| --- | --- |
| 芸能 | 俳優、声優、コメディアン、テレビ司会者、モデル、映画監督、YouTuber、タレント、子役、アイドル、グラビアアイドル、アナウンサー、ラジオパーソナリティ、司会、落語家、講談師、手品師、セレブリティ、インフルエンサー、TikToker、ダンサー |
| 音楽 | 音楽家、歌手、作曲家、指揮者、ソングライター、ラッパー、DJ |
| スポーツ | スポーツ選手、プロレスラー、サッカー指導者、コーチ、野球指導者・監督、バスケットボール・ハンドボール指導者、フィギュアスケートのコーチ、競艇選手、調教師（競馬）、棋士 |
| 知・発明 | 科学者、発明家、数学者、哲学者、技術者、医師、宇宙飛行士、研究者、学者、思想家、心理学者、統計学者、建築家、科学コミュニケーター |
| 歴史・社会 | 政治家、君主、軍人、活動家、外交官、武士、探検家、大臣、知事、統治者、封建君主、公卿、官僚、裁判官、弁護士、実業家、起業家、経営者、ジャーナリスト、宗教指導者、フェミニスト |

- 複数の分野で活動する人は、複数のカテゴリーに出ます。
- どこにも当てはまらない人（作家、画家、漫画家など）は無理に割り当てません。図鑑タブには「部門なし」として出ますが、勝負には使えません。
- ルールは `lib/categories.ts` にあります。Q-ID を足したり除いたりして変更し、`npm run check-categories` で意図した職業か確かめてから、`npm run build-occupation-map -- --refresh` で職業の表を作り直してください。
- **職業の表（`lib/occupation-map.json`）:** 職業ごとに「どのカテゴリーの職業にたどり着くか」を前もって調べた表です。表にある職業は Wikidata に問い合わせずに分類できるので、手札が速く作れます。表にない職業だけ、その場で上位分類をたどります。今の表は、実際の日付ページ 7 日分（8/13・10/29・12/25・2/29・1/1・5/5・7/7）に出てきた 629 種類の職業から作り、そのうち 470 種類がいずれかのカテゴリーに入ります。

### センシティブな人物を隠す

既定でオンです（設定でオフにできます）。次のどちらかに当てはまる人物を手札に出しません。

- 職業（下位分類も含む）が、ポルノ俳優・セックスワーカー・ストリッパー・娼婦、または犯罪者・連続殺人犯など
- Wikidata の日本語の説明に「AV女優」などの語がある

Wikidata の記録に頼っているので完全ではありません。漏れた人は、カードの「このカードを外す」で外せます（端末に保存され、設定画面で戻せます）。

## データの取り方

```
lib/server/birthpage.ts  その日生まれの人物の一覧（日本語版 Wikipedia の日付ページ）
lib/server/wikidata.ts   人物の詳細と職業の上位分類（Wikidata）
lib/classify.ts          カテゴリー分類・センシティブな人物の判定（ネットワークを使わない）
lib/server/images.ts     写真とライセンス（Wikimedia Commons）
lib/server/pageviews.ts  知名度スコア（Wikimedia の閲覧数 API）
lib/server/hand.ts       上をつないで、誕生日 1 つ分の手札を作る
lib/server/cache.ts      手札のキャッシュ
app/api/hand/route.ts    手札（GET /api/hand?date=10-29）
app/api/score/route.ts   選んだ 1 人分の知名度スコア（GET /api/score?title=記事名）
components/              画面
```

外部のサービスへのアクセスはすべてサーバー側で行います。ブラウザーが呼ぶのは `/api/hand` と `/api/score` だけです。

### 人物

1. 日本語版 Wikipedia の日付ページ（「8月13日」など）の「誕生日」の節を、生の wikitext（`index.php?action=raw`）で読みます。人が選んで載せている「その日生まれの著名な人」の一覧なので、**その日生まれの全員ではありません**（8/13 で約 180 人、1/1 で約 1,000 人）。
2. 各記事の Wikidata の Q-ID を引き（リダイレクトも解決）、Wikidata から名前・説明・職業・写真・生年月日を取ります。50 人ずつまとめて問い合わせます。
3. Wikidata で「人間」と登録されていない項目（バンドやグループなど）は除きます。日本語版に記事がない人（赤リンクや仮リンク）は一覧に入りません。

- **名前:** Wikidata の日本語ラベル。なければ英語、多言語共通のラベル、日本語版の記事名（末尾の括弧書きを除く）の順です。
- **ローマ字の名前:** Wikidata の英語ラベルがラテン文字だけのときに使います（公開画面のサイン）。
- **説明:** Wikidata の日本語の説明。なければ日付ページに書かれた説明（「歌手」など）。どちらもなければ「紹介文はありません」と出し、文章を作って補うことはしません。
- **並び順:** 生まれ年の新しい順です。知名度順に並べると、公開前にスコアの大小が分かってしまうためです。

最初は Wikidata のクエリサービス（SPARQL）で「その月日生まれの人」を検索していましたが、重すぎて時間切れになり、使えませんでした。

### 回数制限（HTTP 429）への備え

クラウドの共有 IP から使うと、Wikipedia や Wikidata の API が「リクエストが多すぎる」（429）と断ることがあります。

- 429 を受けたら、5 分間は、Wikidata 側の 1 件ずつの窓口（`Special:ItemByTitle` で記事名 → Q-ID、`Special:EntityData` で項目の中身）に切り替えます。同時に 3 件まで、`Retry-After` に従って待ちます。
- それでも取れなかった人は、その人だけ手札から抜き、手札画面に「一部を読み込めませんでした」と出します。その不完全な手札は保存せず、次に開いたときに取り直します。
- 写真の窓口に断られたときは、待たずに写真なしのカードにします。

### 誕生日の採用方針

- **誰をその日生まれとするか:** 日本語版 Wikipedia の日付ページの「誕生日」の節に載っている人です。
- **表示する生年月日:** Wikidata の生年月日（日の精度まで分かる、最良ランクの値）の月日がその日と同じなら、それを表示します。違えば（旧暦・ユリウス暦の違いや記録の食い違い）、日付ページに書かれた年とその日の月日を表示します。
- **複数の誕生日:** Wikidata に生年月日が複数あるときは「最良ランク」の値だけを見ます（推奨ランクがあればそれ、なければ通常ランク。非推奨は使いません）。
- **暦の違い:** Wikidata の生年月日がユリウス暦で記録されていて月日が一致した人は、詳細画面で注記します。日付ページ側の暦の扱いは、Wikipedia の記載に従います。

### 知名度スコア（Wikipedia の閲覧数）

- **数えるもの:** 日本語版 Wikipedia の記事が、人間によって閲覧された回数（agent = `user`、全アクセス方法）の合計です。補正はせず、そのまま比べます。
- **集計期間:** 直近の完了した月の末日までの 12 か月です。UTC で計算するので、どの端末でも同じ期間になります（例: 2026年10月なら 2025年10月〜2026年9月）。月が変わると、全員の期間がそろって進みます。
- **いつ取るか:** 手札を開くときには取らず、「このカードで勝負」を押したときに、その 1 人分だけ取ります。取っているあいだ、ボタンは「スコアを確認中…」になります。
- **値の固定:** 取ったスコア・集計期間・取得日をカードにコピーして固定します。公開画面には集計期間を出し、期間の違うカードどうしを比べないよう注意書きを出します。
- **0 回と取得失敗の区別:** API が 404（期間中に閲覧記録がない）を返したら 0 回です。それ以外のエラーや時間切れは「スコアを取得できませんでした」と出し、そのカードでは勝負に進みません。
- **記事名の変更とリダイレクト:** 今の記事名で数えるので、改名前の記事名やリダイレクト（別名のページ）経由の閲覧は入りません。期間の途中で改名された記事は、実際より少なく出ることがあります。

### 写真

- Wikidata の画像（P18）を Wikimedia Commons で調べ、ライセンスと作者を確認できたものだけを使います（パブリックドメイン、CC0、CC BY、CC BY-SA）。
- フェアユースなどほかのライセンスの写真や、作者が分からない CC の写真は使わず、頭文字のカードにします。
- 使った写真のクレジット（作者とライセンス）は、カードの詳細画面に出します。

## 前もって作った手札（public/hands）

誕生日を入れたとき、アプリはまず `public/hands/<月-日>.json`（例: `/hands/10-29.json`）を読みます。あればそれを使うので、手札がすぐ出ます（実測 0.2 秒）。なければ、サーバーがその場で作ります（多くの日で約 10 秒、1 月 1 日は約 1,000 人いるので約 30 秒）。

- **中身:** 手札の人物・カテゴリー・写真です。知名度スコアは入れません（「このカードで勝負」を押したときに 1 人分だけ取ります）。読み込んだときの集計期間に合わせて使います。
- **作り方:** GitHub Actions のワークフロー「Build birthday hands」（`.github/workflows/build-hands.yml`）が、1 か月分ずつ作ってこのブランチに保存します。保存すると Vercel が公開し直します。
  - 手動: GitHub の Actions タブ →「Build birthday hands」→「Run workflow」（ない日だけ作る。「すでにある日も作り直す」にチェックで全日）
  - 自動: 毎月 3 日に全日を作り直します（Wikipedia・Wikidata の更新を取り込むため）
- **欠けた日は書かない:** 混雑で一部の人を取れなかった日はファイルを書かず、次の実行で作り直します（その日は、その場で作る動きになります）。
- 手元でも `npm run build-hands -- 10-29` で作れます。

## キャッシュ

| どこ | 中身 | 有効期間 |
| --- | --- | --- |
| サーバーのメモリとディスク（`data/hands/<集計期間>/<月日>.json`） | 誕生日 1 つ分の手札（人物・分類・写真。スコアは入れない） | 集計期間が同じあいだ。月が変わるとキーが変わり、自動で取り直す |
| サーバーのメモリ | 記事ごとの知名度スコア | 集計期間が同じあいだ（サーバーが動いているあいだ） |
| 端末の localStorage | 誕生日、設定、外したカード、選択中のカード | 利用者が変更・リセットするまで |

- **初回の手札（前もって作った手札がない日）:** ある誕生日を初めて開くと、日付ページ（1 回）、Wikidata（50 人ずつ数回）、写真のライセンス確認（50 枚ずつ数回）を問い合わせます。本番（Vercel）で約 7 秒でした。同じ誕生日の 2 回目以降はキャッシュからすぐ出ます。段階ごとの時間は API の応答の `timings` に入れています（画面には出しません）。
- **同時アクセス:** 同じ誕生日の取得が同時に始まったら、1 回にまとめます。
- **Vercel の場合:** ディスクの内容は長くは残らないので、時間がたつと同じ誕生日でも取り直すことがあります。
- **キャッシュを捨てる:** `data/hands/` の該当ファイルを消して、サーバーを再起動します。保存先は `HAND_CACHE_DIR` で変えられます（書き込めないときは OS の一時ディレクトリ）。

## デモモード（開発・確認用）

- URL の末尾に `?demo=1` を付けたときだけ、架空の人物とデモ値で動きます（例: `http://localhost:3000/?demo=1`）。利用者向けの画面には切り替えを出さず、端末にも保存しません。
- 画面とカード操作は実データと同じで、画面上部に「DEMO」、スコアに「デモ値」と出します。
- デモデータがある誕生日は 10月29日・2月29日・1月1日です。次のケースを確認できます: 複数のカテゴリーに入る人、写真あり・なし、スコア 0、スコア取得失敗、日本語版の記事なし、部門なし、センシティブな人物、ユリウス暦、2月29日、候補のいないカテゴリー（2月29日の「知・発明」）。
- 最初の画面に飾っているカード 3 枚は、デモ用の架空の人物です。

## 確認したこと

## 既知の制約

- **全員ではない:** 手札は日本語版 Wikipedia の日付ページに載っている人だけです。
- **作家・画家・漫画家など:** どのカテゴリーにも入りません。必要なら `lib/categories.ts` に「文学・アート」カテゴリーを追加できます。
- **職業の表にない職業:** その場で Wikidata に問い合わせるので、少し時間がかかります。よく使う誕生日で `npm run build-occupation-map` を実行すると表が増えます。
- **回数制限:** 混雑時は、一部の人が手札に入らなかったり、スコアの取得に失敗したりすることがあります（そのときは画面に出ます）。
- **日付ページの書き方:** 「* [[1990年]] - [[人物]]、説明」という行の形を前提に読んでいます。書き方が大きく違う行は読み飛ばします。
